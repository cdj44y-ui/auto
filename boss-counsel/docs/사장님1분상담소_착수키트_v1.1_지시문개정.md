# 사장님 1분 상담소 — 착수 키트 v1.1 (지시문 개정분)

> 작성 2026-10-07 · v1.0 대비 변경: 지시문 4장에 **명세 블록·화면 목록·자기검증·완료 기준** 4요소를 넣음
> 참고: JasonZhu.AI「Claude 5.5 Prompt Library」(Claude 5.5 계열 모델로 만든 영상·모션·게임 공개 프롬프트 모음, 2026-10-06 갱신) — 영상·게임용 모음이라 내용은 직접 쓸 수 없고, **잘 된 프롬프트에 공통으로 들어 있는 구조**만 옮김

## 핵심 3줄
1. 모음집의 결론은 한 문장입니다: **"결과물을 직접 띄워 보고, 화면을 확인하고, 기준에 맞는지 검사하게 시켜라. 그 부분을 지우지 마라."**
2. v1.0 지시문은 "무엇을 만들지"는 충분하고, **"다 만든 뒤 무엇을 직접 확인하고 보고할지"** 가 약했습니다. 그래서 각 지시문 끝에 자기검증과 완료 기준을 붙였습니다.
3. 뼈대는 그대로 두고 내용만 바꿔 다시 쓸 수 있도록 지시문을 **명세 → 작업 → 자기검증 → 완료 기준 → 보고** 5단으로 통일했습니다. 다음 정적 사이트에도 그대로 쓸 수 있습니다.

## 모음집에서 가져온 4가지와 적용

| 모음집 패턴 | 원래 뜻(영상) | 상담소 적용 |
|---|---|---|
| 명세 블록 맨 앞 | 해상도·프레임·길이 고정 | 화면 폭 3종·글자 크기·금지 사항을 맨 위에 고정 |
| 장면 목록 | 장면 순서·전환 시점 | 화면 목록: 첫 화면 → 문 → 카드 → 찾기 → 문의 |
| 자기검증 | 렌더링 → 프레임 확인 → 루프 확인 | 띄우기 → 3개 폭 캡처 → 캡처를 직접 보고 점검 → 콘솔·네트워크 확인 |
| 완료 기준 | 루프 끊김 없음, 박자 일치 | 테스트 통과 수·캡처 수·로딩 시간 같은 숫자로 판정 |
| 뼈대 유지, 주제만 교체 | 같은 틀로 다른 영상 | 5단 틀 고정 → 다음 정적 사이트에 재사용 |

## 개정 지시문 (붙여넣기용)

**지시문 1 — 뼈대**
```
[명세]
- 너는 위너스 「사장님 1분 상담소」 제작자다. 첨부한 시안 HTML이 완성 화면이다. 디자인을 새로 만들지 말고 그대로 옮긴다.
- 레포 sajang-1min. index.html / data/cards.json / data/keywords.json / assets/ / tests/
- 정적 사이트(프레임워크 없음 또는 Vite 정적 빌드). 로그인·DB·쿠키·외부 추적 스크립트 금지.
- 브랜치 → Vercel 미리보기 → PR. main 직접 반영 금지.
[화면 목록] 첫 화면 → 문 12개 → 카드 → 찾기 → 문의 (다크 모드 포함)
[작업] 시안에 박혀 있는 카드 데이터와 키워드 표(KW)를 data/로 분리하고, 화면은 그 파일을 읽어 그린다.
[자기검증] 끝내기 전에 직접 한다.
 1) 로컬에서 띄우고 360·390·430px 폭에서 첫 화면·카드 화면을 캡처한 뒤, 캡처를 직접 보고 시안과 다른 곳을 고친다.
 2) 시안과 새 화면을 같은 폭에서 나란히 캡처해 차이를 목록으로 적는다(차이 0이 목표).
 3) 브라우저 콘솔 오류 0건, 외부 도메인 요청 0건(글꼴 제외)을 확인한다.
[완료 기준] 콘솔 오류 0 · 외부 요청 0 · 시안과의 차이 목록 0건 또는 사유 기재
[보고 1줄] 미리보기 주소 · 카드 수 · 테스트 결과 · 시안 차이 건수
```

**지시문 2 — 안전장치 테스트** (v1.0 6항 유지 + 보완 3개)
```
[작업] tests/에 node로 도는 검사를 만든다. 하나라도 실패하면 배포하지 않는다.
 1) live 카드는 legalRefs마다 verifiedAt(날짜)과 url(law.go.kr)이 있어야 한다.
 2) 카드마다 heart·answer·day가 있고 todo는 정확히 3개다.
 3) 금지어: 무조건, 반드시 처벌, 100%, 승소, 그리고 광고성 「전문 ○○」 표현.
    (「전문가」, 「판결문 전문」은 허용 — 단어 단위로 판정)
 4) data/blocklist.txt의 단어가 어디에도 없다(실명·회사명 방지).
 5) 공개 화면에는 live 카드만 나온다. 미리보기 주소에서만 ?preview=1로 전체 카드를 본다.
 6) verifiedAt이 6개월을 넘은 카드는 테스트에서 경고하고, 화면에서도 live에서 뺀다
    (테스트는 배포할 때만 돌기 때문).
[자기검증]

   (안 걸리는 테스트는 문지기가 아니다)
 - 공개 주소와 ?preview=1 주소에 나오는 카드 수를 각각 세어 status 집계와 맞춘다.
[완료 기준] 테스트 6개 통과 · 6개 모두 일부러 실패시켜 걸리는 것 확인 · 카드 수 일치
[보고 1줄] 통과/실패 수 · 공개 카드 수 / 전체 카드 수
```

**지시문 3 — 연결**

## 반대논거
1. **자기검증이 늘면 1회 작업 시간이 늘어납니다.** 대신 "고쳐 달라" 왕복이 줄어듭니다. 전달 전 왕복 수 기준(G12 오버헤드 심사)으로는 오히려 줄어드는 조항입니다.
2. **클로드 코드의 자기검증은 사람의 확인을 대신하지 못합니다.** 법령 대조(verifiedAt)와 문장 확인은 계속 마케팅 실장·대표님 몫입니다. 자동 검사는 빠진 것을 거르는 그물일 뿐, 내용이 맞는지 판정하지 않습니다.
3. **참고 자료는 영상·게임 모음입니다.** 그래서 구조만 가져왔습니다. 다만 카드의 「2분 영상」을 나중에 만들 때는 이 모음의 설명 영상 프롬프트를 직접 쓸 수 있습니다(이 환경에도 코드로 영상을 만드는 HyperFrames 스킬이 있음).

**[호출조건]** 클로드 코드에 사이트·화면 제작을 맡길 때, 또는 지시문이 "만들어라"로만 끝나 결과를 매번 사람이 고쳐야 할 때 → 5단 틀(명세·작업·자기검증·완료 기준·보고)과 "일부러 실패시켜 테스트 확인" 원칙을 꺼낸다
